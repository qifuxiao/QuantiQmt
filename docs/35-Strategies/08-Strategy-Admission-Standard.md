# Strategy Admission Standard

> Status: Proposed

策略上线不是“回测赚钱即可”，必须证明逻辑正确、数据无泄漏、风险可控、容量可执行和运行可恢复。

## 必备材料

- 策略说明：假设、市场、标的、频率、信号、仓位、退出、失效条件。
- 数据说明：来源、版本、可得时间、复权、缺失和幸存者偏差处理。
- 风险说明：最大敞口、杠杆、回撤、流动性、日损和 Kill 条件。
- 实验报告：样本内/外、滚动验证、成本、滑点、容量和敏感性。
- 运行规格：manifest、参数 schema、checkpoint、指标、告警和停止政策。

## 技术门禁

- 只依赖 Strategy SDK；无 Broker/DB/Redis 直接访问。
- 相同输入、版本和随机种子输出确定。
- 无未来函数；事件时间和数据发布时间正确。
- 回调满足 deadline，资源和输出频率有界。
- 重复/乱序订单事件不会产生重复意图。
- checkpoint 恢复与连续运行结果一致。

## 研究门禁

必须包含样本外和 walk-forward；报告换手、成交率、费用、滑点、容量、回撤持续时间和参数稳定性。禁止只报告 Sharpe/年化收益。基准、无风险利率和交易成本假设必须版本化。

## 晋级门禁

| 阶段 | 最低要求 |
|---|---|
| Backtest | 数据/代码审查、确定性和无未来函数通过 |
| Simulation | 拒单、部分成交、stale、断连场景通过 |
| Paper | 至少 5 个有效交易日，链路/告警/恢复正常 |
| Limited Live | 独立低限额、人工日对账、Kill 演练 |
| Production | 审批、容量与风险预算、20 日稳定观察或委员会批准替代标准 |

## 否决条件

不可解释的收益来源、数据泄漏、对单一参数极端敏感、成本后失效、流动性容量不足、无法恢复、没有 owner/Runbook、绕过 Target/OMS/Risk，任何一项均禁止生产。

## 持续治理

监控实际与预期成交、滑点、暴露、换手、收益分布和数据质量。触发漂移、回撤或异常频率阈值后自动降额/暂停；参数变更和策略新版本重新走相应准入流程。
