# 实盘交易与故障处理

> Status: Proposed

## MiniQMT Adapter

Broker Adapter 只负责连接、请求转换、回报标准化、错误翻译、限速和关联 ID；不得包含风控或订单状态机。SDK 回调数据必须复制为内部不可变 DTO，不能把 SDK 对象泄漏到 Domain。

M1 必须连接 Mini QMT 模拟账号。客户端由操作者先登录；adapter 使用受控配置中的
`userdata_mini`、唯一 session ID、账号 ID 和账号类型连接/订阅。密码不得出现在 Git、
Prompt、task、fixture 或日志；如果券商版本确需 secret，只保存 secret reference。

M1 只允许 `MINIQMT_SIM_READONLY` 与显式门禁后的 `MINIQMT_SIM_TRADING`。账号必须与
精确 allowlist 匹配；无法可靠确认模拟环境时保持 SAFE。默认禁止下单、默认 Kill Switch
生效。真实资金账号和普通 `LIVE` profile 不能通过配置自行解锁。

启动顺序为：加载安全默认值 → 校验路径/API 兼容性 → 连接 → 订阅与只读查询 → 校验
账号/能力绑定 → 对账 → 健康窗口 → 审批恢复屏障。任何失败均不得打开下单能力。

## 心跳与健康

健康状态分为 `STARTING/HEALTHY/DEGRADED/UNHEALTHY`，分别检查进程存活、最近回调、主动查询、行情新鲜度和请求成功率。TCP 连接存在不代表服务可用。

## 故障矩阵

| 故障 | 自动动作 | 交易策略 | 恢复条件 |
|---|---|---|---|
| QMT 断连 | 指数退避重连、告警 | 禁止新单；保留本地撤单意图 | 重连并完成订单/成交对账 |
| 下单超时 | 标记 SUBMIT_UNKNOWN，主动查询 | 禁止同 ID 盲重试 | 确认存在或不存在 |
| 行情陈旧 | 标记 stale、暂停相关策略 | 拒绝依赖该行情的新单 | 连续健康窗口通过 |
| Redis 不可用 | 本地有界缓冲、切 Degraded | 无可靠命令通道时拒绝新单 | Stream/消费位置校验完成 |
| PostgreSQL 不可用 | 断路器、告警 | 无法持久化审计时拒绝新单 | 写入和 Outbox 恢复 |
| Strategy Worker 崩溃 | 独立重启 | 已有订单仍由 OMS 管理 | 状态恢复后手工/自动启用 |
| OMS Leader 丢失 | fencing 旧实例、选主 | 选主期间拒绝新单 | 新 Leader 对账完成 |
| 磁盘满/审计失败 | 严重告警、进入 SAFE | 禁止新单 | 容量恢复并验证写入 |

## 重试规则

只有可判定幂等的查询和命令可以自动重试；使用指数退避、随机抖动、最大次数和总时间预算。下单超时属于“不确定”，走查询与对账，不按普通网络错误处理。熔断器打开时定期半开探测，禁止所有请求同时冲击恢复中的依赖。

## Kill Switch

支持全局、账户、策略和标的级别。触发后原子地禁止新意图，可配置撤销活动订单；操作需要鉴权、原因、操作者、correlation_id 和不可变审计记录。恢复交易不能随依赖重连自动发生，必须满足健康窗口和审批策略。
