# 架构原则

> Status: Proposed

1. **安全优先于可用**：状态不确定时禁止新开仓，允许撤单、查询和人工接管。
2. **OMS 单写者**：OMS 是内部订单状态唯一写入者；逻辑唯一通过 Leader/fencing 保证。
3. **策略只产生意图**：策略不能持有 Broker 凭证，也不能调用执行接口。
4. **Command 与 Event 分离**：命令表达请求，事件表达事实；关键链路不以广播事件冒充调用结果。
5. **热路径隔离阻塞 I/O**：数据库、日志落盘、报表和外部查询不运行在行情回调或交易核心线程。
6. **有界资源**：队列、缓存、重试次数和并发数必须有上限及溢出策略。
7. **业务幂等而非幻想 Exactly Once**：所有外部命令具有稳定 idempotency_key；重复事件可安全消费。
8. **明确权威来源**：外部委托/成交以 Broker 为最终事实，内部意图和风控决策以审计账本为准，持仓资金通过账本推导并与 Broker 对账。
9. **恢复是正常路径**：启动、重连、补报、乱序、重复和差异修复都必须可测试。
10. **可观测性内建**：关键消息携带 event_id、causation_id、correlation_id、occurred_at、source 和 schema_version。
11. **Live/Backtest 共享语义，不共享幻觉**：共享 Domain/Application；替换时钟、行情源、执行和调度器。
12. **基础设施可替换但语义不可漂移**：Adapter 必须通过相同契约测试。

## 禁止项

- `strategy.buy()`、策略直接访问 QMT、策略修改订单/账户/持仓。
- 在 Broker 回调中执行策略计算、数据库事务或阻塞式日志写入。
- 无限重试、无限队列、捕获异常后静默继续。
- 仅凭 Redis 缓存恢复订单事实。
- 使用 wall clock 决定领域顺序；顺序由来源序号、聚合版本和单写者约束决定。
